A visitor gives their name and email; on submit this sends ONE email (via EmailJS, the same provider already used for comment-moderation notifications) to comments-moderator-email in _config.yml, with the visitor's name and a Reply-To of their email address. There is no subscriber list and no automatic sending to anyone when a new issue is published -- the moderator adds the person to whatever mailing tool they use by hand. If a real subscriber database / automated send is ever wanted instead, this whole include should be replaced, not extended.
